# Yvora 1.2 thermal control

Analysis-only CameraX session removes the invisible Preview use case and its surface. Screen-off or severe Android thermal status (API 29+) or reported battery temperature >=43 C pauses the session by clearing and unbinding the analysis use case, releases active drag, clears stale results, and hides the pointer. Recovery requires Android thermal severity <= light and reported battery temperature <40 C (if available) for 15 seconds. These are conservative software policy thresholds, not battery safety guarantees; reported battery temperature is not CPU temperature. Screen-on resumes only when thermal policy permits and requires an open hand before gesture input resumes. No background camera capture while screen is off. Battery saver and moderate thermal state slow processing; idle/no-hand rate is reduced, and active gestures get priority within the thermal budget. Inference duty pacing uses measured worker time. Rates are target maximums, not measured camera FPS. CPU remains the default; no claim of GPU improvement. Camera sensor frame rate may remain OEM-controlled; actual power/temperature improvement requires device testing. No new dependencies. Unit tests cover policy timing, state, and recovery.
