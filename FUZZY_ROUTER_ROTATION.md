# Yvora 1.9-dev — two-hand rotation and local/cloud routing

- Normal, zoom-only and rotate-only are mutually exclusive modes selected in a spinner. Previous zoom preference is migrated. Both transforms require dual-hand tracking, two open-palm samples followed by two closed pinches. Rotate uses angular change (atan2 of cross/dot products), radial stability and tracking memberships with min aggregation and alpha .60. Only one action per open-palm cycle. Two simultaneous bounded Android strokes trace opposite 30-degree arcs around the center over 320 ms, sharing the zoom busy guard. A target app must support rotation; it does not rotate the operating system or produce continuous multitouch. Real device compatibility not established.
- FuzzyAiRouter evaluates Arabic/English local dictionary coverage and lexical set Jaccard compatibility. An entire exact 1–4-action allowlisted plan is required before local preview; no partial/fuzzy-guess execution. BACK/HOME last only. The user must review and prepare the plan and press Run here on the target screen. No network or key needed for local commands. Unknown or ambiguous phrases show the coverage/similarity and recommend editing or explicitly choosing a provider; the separate cloud button confirms exactly what will be sent. Provider results still pass the same gate. No automatic cloud fallback or camera/screen upload. Diagnostic requests remain explicit. 
- Tests cover direction, radial-change rejection, missing-hand rejection, local Arabic/English, negation, ambiguity and plan bounds.
- Prior branches #10–#13 included, not merged yet. Arbitrary gesture trajectories, continuous multitouch, combined transform classifier and contextual screen-aware AI remain open.
