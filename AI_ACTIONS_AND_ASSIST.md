# 1.5-dev — reviewed AI navigation + assisted local gestures
Based on the tested dual-hand branch (PR #8), this PR includes dual cursors. No merge yet.
Provider replies are parsed as bounded exact navigation tokens. A separate confirmation creates an accessibility overlay for at most 25 seconds. The user manually chooses a destination and presses Run here; package identity is checked locally, locked/system/sensitive settings screens are blocked, and each swipe waits for the actual Android completion callback. BACK/HOME terminal only. No taps, text entry, app launches, screen capture or external data upload other than previously approved prompt/diagnostics. Stop AI cancels pending steps (an in-flight 250ms stroke may finish). Running camera suppresses hand injection during plan; manual pinch/swipe stops plan when recognition works. Thermal/screen pause stops session while tracking service runs. No unattended autonomous operation. Actual UI effect is not guaranteed by Android completion callback.
Opt-in assisted gestures use local fuzzy membership of partial finger extension, palm orientation, finger spacing, and existing temporal horizontal motion gate. Feedback presets change tolerance, not ML training; exact manual gestures retained. No new inference model or cloud frames. Only horizontal swipes have relaxed interpretation in this stage. Autonomous free-form intent, voice, context-aware screen operations, adaptive ML training, multi-touch, code self-modification and real device/provider execution testing remain future work.
