# Self-improvement stage 1: diagnostic loop

Manual, consent-gated diagnosis in the existing model lab. Collect aggregate in-memory counts of delivered/hand/stale results, frame age, processing failures, recognition and rejected dispatches; no raw images, screen contents, hand coordinates or other app identities. Counts cover the process lifetime, not a controlled benchmark; dispatch acceptance is not proof of application behavior. The user can inspect exactly what is sent before a single provider request. Provider returns one of three allowlisted recommendation types and human-readable analysis. Only the reversible AUTO detail setting can be applied, through a separate confirmation; no thermal safeguards can be disabled. Investigate-code suggestions are reports only.

Future developer loop: with a separately authorized repository integration, create a sanitized issue containing reproducible steps, assign a coding agent to a branch, require regression tests and review, build signed update, compare before/after metrics on target devices, and revert if degraded. Do not put repository write credentials in the APK or give remote model responses arbitrary shell, code download, or accessibility execution. No automatic PR generation, release deployment, scheduled diagnosis, actual provider calls or on-device comparison implemented in this stage.
